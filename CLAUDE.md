# GrowBucks – working notes

Product intent: `readme.md`. Approved scope: `docs/features.md`. Design
sketches: `docs/design/feature-sketches.html`.

## Layout (pnpm monorepo)

- `apps/mobile` – the product: Expo SDK 57 (React Native 0.86), Expo Router
  (`src/app`), iPhone + iPad (`supportsTablet`). Route groups: `(auth)`
  signed out, `(parent)`, `(kid)`, switched by `Stack.Protected` in
  `src/app/_layout.tsx` from the device's session.
- `apps/web` – Cloudflare Worker (TanStack Start): the growbucks.cash landing
  page and the JSON API under `/api/v1` (file routes in
  `src/routes/api/v1`). D1 + Drizzle live here.
- `packages/core` – TypeScript shared by both, imported as source:
  `growth` (interest engine), `rewards` (task rewards + celebration tiers),
  `validators` and `api` (Zod schemas and the endpoint table), `pairing`
  (codes/tokens). No React, no platform APIs except Web Crypto on the server.

## Tooling

- pnpm only (pinned via `packageManager`). Never use npm/yarn or commit a
  `package-lock.json`. Dependencies allowed to run install scripts are listed
  under `allowBuilds` in `pnpm-workspace.yaml`. Use `pnpm run deploy`
  (plain `pnpm deploy` is a built-in pnpm command).
- Biome for lint + format from the root (`pnpm lint`, `pnpm lint:fix`).
  Double quotes, no semicolons, 80 cols.
- Unit tests live next to logic in `packages/core` (`*.test.ts`, node's
  built-in runner, `pnpm test`). Keep UI tests to a few high-level journeys:
  Maestro for the app (`apps/mobile/.maestro`), Playwright for the Worker
  (`apps/web/e2e`).
- Expo: add native modules with `pnpm --filter @growbucks/mobile exec expo
  install <pkg>` so versions match the SDK. The app needs a dev build
  (`expo-dev-client`), not Expo Go, because of camera/secure store/haptics.
- `apps/web/src/routeTree.gen.ts` is generated by `vite dev`/`vite build`;
  never edit it.

## API conventions

- Every endpoint is declared once in `packages/core/src/api.ts` (method,
  path, body schema, response schema). The server parses with the same
  schema (`parseBody`), and the app calls it via `call(name, …)` in
  `apps/mobile/src/lib/api.ts`. Add endpoints there first.
- Handlers are wrapped in `api()` (`apps/web/src/server/http.ts`); throw
  `HttpError` for user-facing errors with a message that says what to do.
- Auth is `Authorization: Bearer <token>`. `requireSession(request, kind?)`
  / `requireParentWithFamily`. Only hashes of tokens and codes are stored.
- D1 has no interactive transactions; use `db.batch`. Insert parents before
  children (foreign keys are enforced).

## Accounts & devices

- Parents sign in with Apple only (`expo-apple-authentication`). The server
  checks the identity token against Apple's keys (`@growbucks/core/apple`,
  audience `APPLE_BUNDLE_ID`) and keys the parent on `members.apple_sub`.
- A kid's device links by redeeming a one-time pairing code shown on a
  parent's phone (QR of `growbucks://pair/<code>`); it gets a kid-only
  session. Siblings can share a device (one kid session each, switcher on the
  kid home). Parents remove devices from Devices; that revokes every
  session on it.
- The app keeps tokens in the Keychain via expo-secure-store
  (`apps/mobile/src/lib/session.tsx`).

## Money rules

- Money is integer cents everywhere. Format with `formatCents`.
- Rates are ppm per compounding period (1_000_000 = 100%). Cadence is
  daily (default), weekly or monthly, chosen per kid by parents.
- Interest accrues daily in micro-cents (`accounts.accrued_micro_cents`) and
  posts whole cents at the end of each period; the remainder carries.
- Boosts multiply the accrual for 7 days (`boosts` table, one active per kid).
- Tasks carry a rate, cash or no reward; today's rate = floor + rate rewards
  done today, capped at the ceiling. The UI must use `checkOff` from
  `@growbucks/core/rewards` to decide what to animate so server and client
  agree. Haptics follow the tier (`apps/mobile/src/lib/haptics.ts`); iPads
  have none, so animations must carry the moment on their own.
- `stepDay` in `@growbucks/core/growth` is the single source of truth: the
  nightly job and every projection/what-if use it. Change it only with tests.
- The ledger (`transactions`) is append-only; balance = sum of amounts.
- Parents write money in/out and settings; kids read, explore what-ifs,
  check off tasks, and propose tasks/rewards/rate changes.
